Delete memories

Screens for deleting a saved memory on Android: the entry points, the Undo snackbar, the empty library, and the error state. Each one is built and tagged Shipped. Full spec: Delete memories design.

Shipped The More actions menu, the long-press shortcut, the TalkBack custom action, the Undo snackbar and error, the empty library, and focus after a delete are shipped on Android. Shipped · 1 · Entry points

Detail menu, long-press, and TalkBack action Shipped Android only

The primary route is the More actions menu in the detail header. Long-pressing a list card starts the same delete, and every card also exposes a TalkBack custom action, so no route depends on a gesture alone.

Shipped · 2 · Undo window

Snackbar and commit failure Shipped Android only

The memory leaves the list at once. The Undo snackbar sits above the dock for 10 seconds. If the commit fails when the window ends, the memory returns and an error snackbar explains why. It has no action.

Shipped · 3 · Empty library

Empty state after the last delete Shipped Android only

The empty state replaces the cards only, and the heading stays. It is not shown while a recording is still being saved. Undo can appear above it, and Undo returns to the list.

Flow · Timing

From tap to purge Shipped

The app hides the memory at once and writes the soft delete only when the Undo window ends. The purger never sees a memory inside the window, so Undo needs no new service method.

1Hide nowMemory leaves the list. Playback stops if it was playing.
2Undo or waitUndo within 10 seconds shows it again. Nothing is written.
3Commit onceThe window ends and delete(id) is written. The memory stays hidden.
4Purge laterThe next run removes audio, speaker rows, and the record. Runs at launch and every 15 minutes.
