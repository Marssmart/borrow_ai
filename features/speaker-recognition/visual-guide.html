BorrowAI · Feature guide

BorrowAI features

What the app does today (Shipped sections) and the speaker recognition screens still being designed (Mockup sections). Speaker recognition master spec: SPEAKER_RECOGNITION.md.

Shipped sections show what the code in 1.9.6 wires up. Mockup sections are designs that are not built yet. Android only marks features whose runtime exists only on Android (iOS has the recorder, player and microphone permission, but no transcriber, summarizer or category model yet).

Shipped · 1 · Navigation

Bottom dock and pager Shipped

Three icon tabs: Record, Memories, Settings. Tapping a tab moves to its page, and swiping between Record and Memories still works. Opening a memory swaps the dock for two buttons: a highlighted Memories item and a back arrow. The highlight moves as the swipe starts, not after it settles.

Shipped · 2 · Capture

Recording screen Shipped

Tap or hold the record button. A hold records until release, a tap records until tapped again. While recording the screen shows the elapsed time and, on Android, a live transcript. A progress ring around the button shows model downloads. Recordings are saved as M4A and transcribed in the background (transcription is Android only; iOS saves the recording without a transcript).

Model setup picks a tier from device RAM, then downloads the live voice, high-quality voice and summarization models one after another. Setup progress is shown on the capture screen and does not block recording.

Shipped · 3 · Capture problems

Permission, setup and recording failures Shipped

Every failure has a message. Microphone permission shows a rationale with Allow, or an Open Settings button once Android stops asking. Failed model downloads say whether the network, the storage or the verification failed, and retry on the next launch. A recording that cannot start or save shows a dialog and creates no memory.

Shipped · 4 · Saved memories

Memory list and detail Shipped

Each card shows the date, up to three category chips, a summary and the original transcription, and one “Play recording” button. Tapping a card opens the detail view. A notice appears when summaries are paused because the summary model is not downloaded yet. A memory shows “Waiting for transcription…” until its transcript is ready, or “Transcription failed” after five failed attempts.

Shipped · 5 · Background pipeline

From recording to categorized memory Shipped

Everything after recording runs without the user asking, and each step reports to the background activity indicator. Jobs pause while a recording is in progress.

1RecordAudio is saved as an M4A file and a memory is created as pending.
2TranscribeBatch transcription runs in the background, with retries and a startup sweep. Android only
3SummarizeOne short on-device summary. Paused if the model is missing. Android only
4CategorizeUp to three categories scoring 75 or more, new ones proposed when needed. Android only
5RecoverOrphaned recordings become memories again. Deleted memories and their audio are purged.

Shipped · 6 · Background activity

Background activity indicator Shipped

A small pill at the top of every screen with a spinner and the names of work the app is doing on its own. It names up to two activities, in a fixed order, and shows the rest as “+N”. It fades out when the last activity ends. Activities: Downloading models, Transcribing, Analyzing speakers, Summarizing, Categorizing, Cleaning up.

Shipped · 7 · Settings

Settings screen Shipped

No longer a placeholder. It currently holds one switch, the background activity indicator, on by default and stored in its own local collection. The speaker recognition settings below are mockups.

Shipped · 8 · Documentation

GitHub Pages docs site Shipped

A static site under docs/, generated by scripts/build_docs.py from site/content/*.md and each folder under features/. It covers how the app works, architecture, models and privacy, platform status, development, and feature guides, including this one. Run the script after changing content, and commit the regenerated docs/.

Shipped · 9 · Speaker data layer

Speaker recognition foundations Shipped UI is mockup

Shipped in 1.8.0 with no interface: a speaker library and per-memory speakers in a separate local collection, speech clustering, a playable sample per speaker, and library matching. Memories gained speaker analysis status fields, and purging a memory removes its speaker data. The feature is off by default and no speech model is bundled, so no analysis runs yet. The sections below show the planned UI.

Mockup · 1 · Memory list

Speaker chips on each row

Up to three chips per row. Recognized names are filled teal, unknown speakers are outlined, and pending analysis is muted. Extra speakers collapse into “+N”.

Mockup · 2 · Memory detail

One card per speaker

Each card plays only that speaker’s sample from the original recording. Only one sample plays at a time. Unknown speakers get an Assign action. Matched speakers get Change, and auto-matched speakers also get “Not this person”.

Mockup · 3 · Speaker library

Rename, merge, delete

Reached from “Speakers ›” in the memory list header (to confirm). Deleting a speaker never deletes memories. Their chips become “Speaker N” again. Merging combines voice samples, and memories keep their names.

Mockup · 4 · Settings

Opt-in and re-analysis

Off by default. Turning it on shows a consent screen first, and no analysis runs until the user agrees (master spec §9.8, Q-7). The privacy line and consent text are required copy (master spec §13). Withdrawing consent deletes all speaker data. Re-analysis is enabled as soon as the user opts in, with no separate control. It is also queued on speaker creation or model upgrade, and drains in the background on app launch.

Mockup · 5 · Pipeline

What the user sees, step by step

Analysis runs after transcription, so transcription status is never blocked by speaker work.

1SavedRecording is saved. The row shows no chips yet.
2AnalyzingPending chips appear while the job runs.
3MatchedKnown speakers appear with their names.
4UnknownOther speakers show as “Speaker N”.
5AssignedUser names an unknown speaker. Chip and card update at once.
