BorrowAI · Feature guide

Speaker recognition

Shows who spoke in a memory. Chips on each list row, one card per speaker in the detail view with a playable sample, and an assign action that links unknown speakers to people the user has already named. All analysis runs on-device. Master spec: SPEAKER_RECOGNITION.md.

1 · Memory list

Speaker chips on each row

Up to three chips per row. Recognized names are filled teal, unknown speakers are outlined, and pending analysis is muted. Extra speakers collapse into “+N”.

2 · Memory detail

One card per speaker

Each card plays only that speaker’s sample from the original recording. Only one sample plays at a time. Unknown speakers get an Assign action. Matched speakers get Change, and auto-matched speakers also get “Not this person”.

3 · Speaker library

Rename, merge, delete

Reached from “Speakers ›” in the memory list header (to confirm). Deleting a speaker never deletes memories. Their chips become “Speaker N” again. Merging combines voice samples, and memories keep their names.

4 · Settings

Opt-in and re-analysis

Off by default. Turning it on shows a consent screen first, and no analysis runs until the user agrees (master spec §9.8, Q-7). The privacy line and consent text are required copy (master spec §13). Withdrawing consent deletes all speaker data. Re-analysis is enabled as soon as the user opts in, with no separate control. It is also queued on speaker creation or model upgrade, and drains in the background on app launch.

5 · Pipeline

What the user sees, step by step

Analysis runs after transcription, so transcription status is never blocked by speaker work.

1SavedRecording is saved. The row shows no chips yet.
2AnalyzingPending chips appear while the job runs.
3MatchedKnown speakers appear with their names.
4UnknownOther speakers show as “Speaker N”.
5AssignedUser names an unknown speaker. Chip and card update at once.
