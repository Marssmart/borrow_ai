The search field sits above the list and matches the title, summary, and transcript. The field, the count line, and the category chips are built. Search and chips combine.

Shipped · 2 · No results

No-results states Shipped Android only

A no-results state names the query, explains what is searched, and offers the clear actions. A library with no memories at all shows the empty state from the delete design instead. The first preview is built in phase 3. The second is built too, but the chip rules in section 7.4 only offer categories that a memory uses, so a chips-only search always has a match and this state is a fallback. The third is a mockup of the delete design's empty state, which is not built here.

Matching examples Shipped

These examples describe the in-memory matcher. A term is found as a substring, in any of the three text fields, ignoring case. Every term must be found.

QueryMemory textResultWhy
budgetSummary: Budget review moved to Friday.MatchCase-insensitive.
meetTranscript: we meeting at nine.MatchSubstring, so the partial word matches (AC-1.7).
tent busTitle: Trip. Transcript: bring the tent. Summary: check the bus.MatchEach term matches a different field.
tent busTranscript: bring the tent only.No matchEvery term must be found.
dentistMemory still being transcribed, no text yet.No matchPending text is never searched (AC-1.6).
caféTranscript: cafe with the team.No matchAccents are not folded in v1 (Q-1).
